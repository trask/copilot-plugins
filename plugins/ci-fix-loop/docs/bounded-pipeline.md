# Bounded Pipeline calls

PR Pipeline can add `--bounded-step` to the internal `pipeline` command. Repeat the same target, state path, pipeline run and position, model, policy, and `COPILOT_AGENT_SESSION_ID` until it returns a terminal result. Each call inspects checks once, dispatches or observes one hosted repair, or requests one CI rerun. `result: waiting` with exit code 0 means work remains pending. It is never CI clearance.

The hosted helper prints pending v5 JSON to stdout for direct CLI calls. Under managed execution, the coordinator reads pending JSON from the sealed child `workflow_result`. The helper keeps its checkpoint beside the result path and writes the final result file only after completion; the coordinator reads that file after the child exits successfully. The standalone `run` command and `pipeline` without `--bounded-step` keep their synchronous behavior. An uncertain hosted dispatch stays bound to its original request. The coordinator does not send another request.
